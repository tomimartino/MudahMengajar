# Design & UX Preferences

- Visual style: modern, minimal, clean, professional, and friendly — not a generic admin template. Confidence: 0.9
- Prefers light background, white cards, soft borders, rounded corners, generous spacing, and clear typography. Confidence: 0.85
- Uses a single consistent primary color (e.g., Emerald, Indigo, or Blue). Confidence: 0.85
- Consistent status colors: green = done/paid/present, yellow = pending/warning, red = late/absent/overdue, gray = not started. Confidence: 0.9
- Avoids too many gradients and too many colors. Confidence: 0.85
- Mobile-first responsive design (teachers often use phones): touch-friendly forms, large buttons, tables collapse to cards, bottom navigation or drawer. Confidence: 0.9
- Every page has an empty state (no bare empty tables); prefers skeleton loading over spinners; every mutation shows loading/success/error feedback via toast. Confidence: 0.85
- Prefers streamlined, minimal forms: removes optional/redundant fields when their value can be auto-derived or handled later (e.g., dropped the initial-payment section; schedule form asks only for start time and derives end time from the configured duration). Confidence: 0.85
- Prefers schedule entry by day-of-week + time + number of meetings (system auto-fills the calendar, e.g., Mon+Wed × 12 meetings = 12 slots) over picking explicit dates/date ranges. Confidence: 0.85
- Prefers schedule-time entry via a checkbox toggle: by default one shared start time applies to all selected days, and checking "jam mulai berbeda untuk tiap hari" reveals per-day start-time inputs (e.g., Wednesday 14:00, Thursday 12:00). Confidence: 0.85
- Prefers consolidating features and avoiding duplicated UI: merges closely-related pages into tabs (e.g., sessions+attendance), relocates secondary features (e.g., schedule calendar) into the dashboard, removes redundant panels when the same info is available elsewhere, and drops sidebar nav items (Profil, Pengaturan) that duplicate the top-right avatar menu. Substantial standalone features are instead elevated to their own sidebar nav item rather than staying a sub-tab (e.g., Pembayaran split out of the Murid tab into a dedicated /payments sidebar entry on desktop and mobile). Confidence: 0.85
- Separates the public-facing profile/portfolio (identity, bio, achievements, rate, teaching history) from account settings, styled after LinkedIn; public-facing fields like learning method live on the profile so parents/guardians can see them. Confidence: 0.85
- Prefers Profil and Pengaturan as two separate items in the avatar/user dropdown menu rather than one combined "Profil & Pengaturan" entry. Confidence: 0.8
- When auto-generating a schedule from selected weekdays, the first session starts on the record's creation date if that day is selected and the start time hasn't passed yet; otherwise it begins on the next selected day (never a blanket "tomorrow"), avoiding immediately-overdue sessions. Confidence: 0.8
- Prefers pre-filled sensible defaults over blank fields (e.g., a package start date defaults to today, still editable). Confidence: 0.7
- Prefers minimal, curated notifications focused on immediately actionable items (today's schedule, remaining package sessions, payments) over forward-looking reminders like upcoming schedules. Confidence: 0.8
- Wants app notifications to reach the user directly on their phone (push), not only shown in-app; when offered delivery channels, chose free browser-native Web Push over Telegram, a paid WhatsApp gateway, or email. Confidence: 0.85
- Prefers contextual, profile-driven form options: filters dropdowns to only what applies to the teacher (e.g., student school-level choices limited to the teacher's teaching_levels, keeping the student's existing level visible on edit). Confidence: 0.8
- Prefers human-readable, friendly public URLs (custom slugs like /guru/paktomi) over random identifiers/UUIDs for shareable profile links. Confidence: 0.9
- Prefers a dedicated custom confirmation/success page for post-action states (e.g., an "Email berhasil diverifikasi" page with a green check icon and a CTA to continue) instead of silently redirecting to the dashboard or a raw callback. Confidence: 0.7
- Prefers branded, polished HTML email templates (inline-styled, brand-color header, single clear CTA button, plus a plain-text fallback link) over plain default provider templates like Supabase's bare "Confirm your email" text. Confidence: 0.7
- Prefers simple data/statistics presentation via summary cards + tables over charts/graphs; explicitly asks for monthly-income figures as cards (e.g., a grid of monthly income cards on /finance). Confidence: 0.7
- Prefers UI labels that match the domain concept: student status in the student list/tab uses Aktif/Nonaktif (active/inactive), while Hadir (present) is reserved for attendance contexts such as the detail page. Confidence: 0.7
- Wants the app to show a proper branded icon everywhere it can be saved or installed — browser tab/favicon and PWA/shortcut icons on laptop and phone home screens — rather than a generic or random placeholder icon. Confidence: 0.7
- For exported/downloaded documents (e.g., an invoice PDF), prefers the output to contain only the relevant content itself (just the invoice card) with no app header/sidebar/chrome. Confidence: 0.85
- Prefers parallel forms over the same record to stay consistent: a secondary entry point (e.g., "Isi Materi" for already-completed schedules) should expose the same fields/labels/layout as the primary form ("Selesaikan"), dropping only the fields that don't apply (switch jadwal, durasi). Confidence: 0.6
- Prefers auto-calculated form fields to be derived from other inputs and shown read-only/non-editable instead of letting the user type the derived value (e.g., package price = per-session rate × number of sessions). Confidence: 0.85
- When a form field becomes auto-calculated/derived, removes its required-field validation and the `*` required marker so it no longer triggers a "wajib diisi" warning (e.g., "Harga paket wajib diisi" after package price became rate × sessions). Confidence: 0.6
- Prefers checkbox toggles for optional side-effects so the user explicitly opts in/out of a secondary change — except schedule cancellation, which the user later made automatic (see next bullet). Confidence: 0.6
- Prefers schedule cancellation to apply its package/financial side effects automatically without an opt-in toggle: decrement the remaining meeting count and reduce the package price + related invoice by the per-session rate. Confidence: 0.8
- Prefers dropdown option panels to open below the trigger field rather than aligned alongside or overlapping the field. Confidence: 0.7
- Prefers forms/dialogs to have a fixed max height with internal scrolling when content exceeds the viewport, rather than growing unbounded. Confidence: 0.8
- Prefers splitting a combined month-year dropdown into two separate dropdowns (Bulan + Tahun) to keep option lists short and avoid long scrolls. Confidence: 0.8
- Prefers related form fields stacked vertically with the source input directly above its derived/auto-calculated value (e.g., "Tarif per pertemuan" above "Harga paket") rather than laid side-by-side in a wide grid. Confidence: 0.7
- Prefers filter/dropdown rows to be consistently labeled and bottom-aligned (label above each control, container `items-end`) so every control lines up instead of appearing misaligned. Confidence: 0.6
- Prefers period-scoped summary card grids that stay fixed and non-reordering: the grid shows a stable set (e.g., the 12 months of the selected year in Jan–Dec order), clicking a card only highlights/selects it without reordering or showing cards from other periods, and month selection happens through the cards themselves rather than a separate month dropdown. Confidence: 0.7
- Prefers row-level actions collapsed into a three-dot (⋮/kebab) dropdown menu per row (e.g., Invoice / Catat Pembayaran / Hapus) rather than a column of inline icon buttons, and wants that same row-action pattern reused consistently across tabs (Siswa dan Pembayaran). Confidence: 0.8
- Edit forms should pre-fill every field with the existing data saved in the database (not just the basic identity fields) — e.g., the student edit form loads saved schedule days/times, start date, and location back into the same fields as the add form. Confidence: 0.85
- Prefers the dashboard summary cards laid out as a 2×2 grid (two per row) rather than a single row of four, with operational stats on top (Jadwal Hari Ini, Siswa Aktif) and financial stats below (Belum Bayar, Pendapatan). Confidence: 0.65
- Prefers grid cards/summary tiles to be uniform in size and height so they look consistent and not visually awkward (e.g., equal-height dashboard stat cards, removing extra hint text that made one card taller). Confidence: 0.7
- Prefers a simplified two-state attendance model: Hadir (recorded automatically when the user completes a session) and Dibatalkan (set via the cancel action), rather than a richer set of attendance statuses the user must pick from. Confidence: 0.8
- For cancellation/destructive actions, prefers an optional free-text note field so the user can record a reason without it being required (e.g., "Keterangan (opsional)" when cancelling a schedule, saved to the record's notes). Confidence: 0.7
- Prefers cancelled/closed records to remain visible in lists with their status shown (e.g., cancelled schedules appear as "Dibatalkan" in the list below the calendar) rather than being hidden or filtered out. Confidence: 0.7
